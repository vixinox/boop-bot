# 桌面伴侣数字孪生与状态机调试台路线图

本文记录产品当前目标与行为、整体技术架构和开发路线，随项目进展持续更新。具体代码行为、组件设计和接口细节由代码及后续技术文档说明。

实施进度：阶段1–4及 Stage 4 追加的情绪互动/语义角色动作已实现并通过自动验证；当前运行时以 Stage 4 规格为准。真实模型上的复杂视觉/触摸验收及 MP4 演示留待人工完成。已实现行为、已知 GLB 限制和验证记录见[Stage 4 开发规格](./impl/stage-4/stage-4-development-spec.md)。

## 产品目标与范围

构建一个面向桌面浏览器的桌面伴侣机器人数字孪生原型，并提供开发者状态机调试工作台。原型使用 `RobotExpressive.glb`，以 Vite/React 浏览器端呈现舞台与场景；Node 服务代理 LLM Responses API。当前不引入用户账户、数据库或真实硬件控制。

## 当前代码基线

### 伴侣舞台

- 展示机器人和圆形舞台平台。
- 舞台覆盖 header 以下可用视口；鼠标拖拽可无水平角度边界地旋转相机，俯仰角保持安全限制，滚轮可缩放，并可复原当前尺寸适配后的默认构图。
- 初始动画是循环 `Idle`；AI 时间线和直接点按动作在结束/取消/被打断后恢复到 Idle 或当前行为阶段。
- 当前相机支持拖动旋转、平移、滚轮/双指缩放和复位。用户镜头变化会让头部先转；持续的大角度变化后躯干跟随。AI 相机命令不改变用户注意力目标。
- 首发直接互动为头/躯干/手部点按：头部使用现有 `Yes` 点头表达亲近，躯干短暂看向触点，手部播放 `Wave`；明确赞许语义时 AI 可用 `ThumbsUp`。拖动不是触摸。

### Inspector 与播放

Inspector 可选择现有14段动画 clip，调节骨骼旋转偏移和 `Angry` / `Surprised` / `Sad` morph 权重。行为运行时独立管理对话阶段、反应和注意力；明确 Inspector 操作取得手动所有权，恢复伴侣控制后回到当时有效阶段。页面不保存角色、场景或聊天会话。

## 整体架构与技术选型

- **应用外壳：** Vite + React + TypeScript，构建纯前端单页应用；原型阶段不引入路由。
- **三维舞台：** React Three Fiber + Drei；使用 Three.js 动画能力控制角色骨骼动画及三维状态插值。
- **状态与交互：** Zustand store 分别管理动画/Inspector、场景数据和产品级行为事件/仲裁。Three.js 运行时独占模型对象、mixer 和逐帧骨骼写入。
- **动效分工：** Three.js / R3F 负责角色和三维对象；GSAP 负责界面动画。镜头过渡优先沿用 OrbitControls 阻尼，仅在不足时由 GSAP 补充，避免二者同时驱动相机位置。
- **样式与代码质量：** Tailwind CSS 与 shadcn 组件；全局语义 token 定义于 `src/styles.css`，项目视觉约定见 `docs/design-system.md`；Oxlint 用于代码检查，Oxfmt 用于格式化。
- **开发基线：** pnpm + Node.js LTS。
- **智能驱动：** LLM 经 Node 服务生成回应和结构化工具调用；浏览器验证工具参数并拥有机器人、场景和相机运行时状态。用户触碰和镜头注意力属于本地行为输入，不发送给 LLM。

## 开发路线

### 阶段 1：舞台与基础互动

搭建应用和三维场景，加载角色模型与程序化桌面底座；实现 Zustand 状态转换、动作平滑切换、基础情绪表现、快捷互动、休眠/唤醒控件、对话气泡，以及 `Angry` / `Surprised` / `Sad` 三个独立表情权重的基础调节。应用壳保留 header 并扩展为全视口舞台，支持无水平角度边界的相机旋转、受限俯仰、滚轮缩放与视角复原，窄屏控制使用 Sheet，并统一执行 shadcn 项目风格。阶段1不包含自然语言输入、本地规则识别、空间触摸区或完整 Inspector。

### 阶段 2：动画选择与伴侣控制台

重构控制面板与骨骼/动画运行时。单一常驻 Inspector 提供全部 clip 选择；最初包含 Auto 导演和指针注意力，后续阶段3重构已移除这两项。阶段2文档作为历史实现记录保留，不代表当前代码行为。

### 阶段 3：AI 动画时间线与场景创作

让 Boop Bot 从现有动画中选择有限时间线，并提供场景和相机工具。Stage 4 已将临时动作结束规则扩展为自动恢复 Idle 或当前聊天阶段，并加入用户镜头注意力。

### 阶段 4：反应式伴侣行为与情绪互动（实现完成，人工验收待进行）

已交付行为阶段、动作所有权与恢复、普通聊天轻量阶段反馈、用户镜头注意力、角色触碰反应、现有 Idle 复用、表情语义和行为诊断。首发直接互动为头部、躯干和手部点按；头部按住不在范围内；拖动镜头不会触发触碰反应。本地触碰不依据原始聊天文本推断情绪。资源审查只使用现有 GLB 与程序化姿态，发现不足记录为限制，不新增资源、不更换模型或重做 rig。自动检查已完成；真实模型的视觉和手势验收待人工执行。完整实现与限制见[Stage 4 开发规格](./impl/stage-4/stage-4-development-spec.md)。
追加开发已加入本地中文规则驱动的中性、开心、安慰、困倦四态；输入栏提供摸摸头、夸夸它、哄它睡觉/叫醒快捷按钮。`perform_companion_action` 只开放 greet、affection、praise、celebrate、comfort、sleep、wake 七种语义动作，睡眠保持循环 Idle 并低头直到唤醒；摸头和夸奖会先唤醒再执行。未开放任意骨骼参数，也没有修改场景工具所有权。继续使用现有 GLB 和程序化姿态，不新增素材。自动验证已全部通过；实机视觉验收及 1–2 分钟 MP4 由人工验收流程完成，操作清单见[Stage 4 开发规格](./impl/stage-4/stage-4-development-spec.md)。
近期追加的恢复修复加入权威 Auto/Manual 模式：AI 演出工具串行排队（每用户轮最多 3 项），用户动作、请求失败、页面隐藏和手动接管按 ID 清理临时演出；Available clips 为一次性预览并自动恢复 Auto，Inspector 的 Auto 入口可从任意非挂起状态幂等恢复。模型统一取消工具为 `cancel_companion_presentation`，场景动画仍独立运行。
